이 step 밖이다 — 사용자가 한다.

## 작업

### 1. `docs/PRD-v2.md` 에 §21 을 새로 쓴다

`## §21 외부 도구 — VS Code 와 터미널 (2026-08-24 · 사용자 결정)` 로 시작한다.
§20 을 형식의 본으로 삼는다. 담을 것:

- **왜 들어왔나** — 1구간(§20)이 `FoldOrder 1` 을 비워 둔 자리다
- **포트 둘을 가른 이유** — 탐지와 실행은 실패의 계약이 다르다 (조용히 `null` /
  말해야 하는 `LocationErrorKind`). 열거와 조작을 가른 v1 의 수와 같다
- **`[VS]`** — App Paths **만** 본다 (HKCU → HKLM). **`PATH` 로 폴백하지 않는 이유**를
  적어라: 그러면 "VS Code 를 지우면 비활성이 된다" 를 확인할 길이 없다.
  에디터 설정은 만들지 않았다 — 도그푸딩이 요구하면 그때 든다
- **`[>_]`** — 프리셋 다섯 + 사용자 지정. **프리셋 표를 실측값 그대로 싣는다**
  (step 0 의 실행 파일·인자 표 + step 3 의 탐지 순서 표)
- **`{path}` 하나만 치환하는 이유** — 토큰이 둘이 되면 어느 것이 되는지 사용자가 시험해
  봐야 한다. **따옴표를 우리가 붙이지 않는 이유**도 함께
- **`\\server` 루트에서만 비활성** — `IsNetworkServer` 다. `IsNetwork` 가 아니다.
  UNC 아래는 정상적인 작업 디렉터리이고 막으면 NAS 에서 기능이 통째로 없어진다
- **탐지는 창이 다시 보일 때마다** — 상주 앱(ADR-003)의 대가이자 이득이다
- **접힘 표를 갱신한다** — §20 의 `FoldOrder` 표에서 `1 | (비어 있다)` 행을
  `1 | 외부 도구([VS]·[>_]) | 가장 먼저` 로 바꾸고, **폭 실측 표도 다시 계산한다**:
  툴바 합이 `347 → 420` 이 된다 (버튼 32 둘 + 구분자 9 하나). step 8 의 `summary` 에
  실제 값이 있으면 **그것을 쓰고**, 없으면 계산값을 쓰되 *"계산값이고 실측 전"* 이라고
  명시해라
- **§글리프를 고른 자리** — 후보를 실물 16px 로 그려 보고 골랐다:
  - `E756`(CommandPrompt · C:\ 박스)을 기각했다. **테두리 사각이라 `E15B` 와 같은
    계열로 읽히고, 16px 에서 박스 안 글자가 뭉개져 뜻이 안 온다** — `E707`(MapPin)을
    기각했던 것과 같은 실패 모양이다
  - `E943`(`{}`)을 `[VS]` 후보로 기각했다. 획이 가늘어 선 계열에 섞이고 'VS Code' 가
    아니라 '코드' 를 뜻한다
  - **그래서 벡터 Path 다.** 상용이 아니므로 VS Code 리본을 그대로 쓴다 (사용자 결정)
  - **이것이 `DESIGN.md` §7 의 계열 규칙을 셋째로 늘린다** — 선 · 사각 · **채우기**
  - **대가를 명시한다**: 채우기 아이콘 둘은 기존 외곽선 글리프보다 무겁다. 툴바에서
    튀는지는 사람이 판정한다
- **§값을 치르고 배운 것** — 이 구간에서 실제로 값을 치른 것만 적어라.
  step 0~8 의 `summary` 와 `error_message` 에 없는 것을 지어내지 마라

### 2. `docs/DESIGN.md` §7 을 갱신한다

- 아이콘 표에 행 둘을 늘린다:
  `외부 도구 — VS Code / 터미널 | **글리프가 아니라 Path** (ExternalEditorGeometry ·
  ExternalTerminalGeometry) — 아래 참조`
- 표 아래에 블록 하나를 늘린다: **왜 이 툴바에서 처음으로 글리프를 안 썼는가.**
  위 §1 의 기각 사유 둘과 "계열이 셋째로 갈린다" 를 적는다
- **`docs/DESIGN.md` §7 이 지금까지 세운 질문 둘**(*눈에 멈추는가* · *뜻이 오는가*)에
  이번에 **셋째가 붙었는지** 판단해 적어라 — *"그 글자가 아이콘 폰트 안에 있는가"* 는
  이미 v0.8.3 에서 붙었다. 이번 것은 *"아이콘 폰트 안에 뜻이 오는 글자가 아예 없으면
  어떻게 하는가"* 이고, 답이 **Path 로 나간다**는 것이다

### 3. `docs/ARCHITECTURE.md` §2 포트 표에 두 줄

step 1 의 `summary` 에서 정확한 시그니처를, step 3·4 의 `summary` 에서 구현 클래스
경로를 가져온다.

```
| `IExternalToolCatalog` | 설치된 외부 도구를 찾는다. 실패는 null, 취소만 예외.
  **캐시하지 않는다** — 상주 앱이라 창이 다시 보일 때마다 다시 묻는다.
  구현 `Shell/Tools/AppPathsToolCatalog.cs` (COM 이 아니라 STA 도 정리도 없다) |
| `IExternalToolLauncher` | 외부 도구를 그 폴더를 작업 디렉터리로 띄운다. 실패는
  `LocationErrorKind`, 던지지 않는다 — 실패가 정상 상황이라 호출자가 상태표시줄
  한 줄로 만든다. 구현 `Shell/Tools/ProcessToolLauncher.cs` |
```

### 4. ADR 을 하나 더할지 판단한다

**필요하면 `ADR-022` 를 쓰고, 필요 없으면 안 쓴 이유를 `docs/ADR.md` 에 적지 말고
`summary` 에만 적어라.**

판단 기준: *되돌리기 어려운 구조 결정이 있었는가.* 후보 셋:

- **포트를 둘로 가른 것** — 되돌리기 어렵고 근거가 있다 (실패 계약이 다르다). ADR 감이다
- **에디터 탐지를 App Paths 하나로 못박은 것** — 확인 가능성을 위해 기능을 좁힌
  결정이다. ADR 감이다
- **툴바 아이콘에 Path 를 들인 것** — 스타일이 하나 늘고 앞으로 이 길이 열린다.
  `DESIGN.md` §7 이 정본이면 충분할 수도 있다

ADR 을 쓴다면 형식은 ADR-021 을 본뜬다: **맥락 · 결정 · 왜 · 기각한 대안 · 대가.**
**대가를 반드시 적어라** — 이 저장소의 ADR 은 전부 그것이 있다.

### 5. `.harness/HANDOFF.md`

- **§현재 상태** — 브랜치 · 버전 `0.9.0` · **테스트 총계**(실제 값을 게이트에서 읽어라,
  추정하지 마라) · 게이트 4종 결과
- **§포트 현황** — **17/17 → 19/19.** 표에 두 줄을 늘린다 (§3 과 같은 내용)
- **§다음 작업 0** — 지금 *"2구간(v0.9.0) — 외부 도구. 다음 축이다"* 인 절을
  **"끝났다. 사람 확인 전"** 으로 바꾸고, **사람 확인 항목 일곱**을 그대로 옮긴다:
  1. `C:\` 에서 `[>_]` 가 WezTerm(사용자 지정 `wezterm-gui.exe` + `start --cwd "{path}"`)
     으로 그 경로에서 열린다
  2. `\\10.10.10.23\home` 에서도 1번이 되고 `\\10.10.10.23` 에서는 둘 다 회색이다
  3. `[VS]` 가 현재 폴더를 연다. VS Code 를 지우거나 App Paths 를 임시로 옮기고 창을
     숨겼다 다시 보이면 비활성이 된다 — **확인 뒤 반드시 원상복구한다**
  4. `[VS]`·`[>_]` 실루엣이 16px 실물에서 서로 구분되고 기존 계열(선 · 사각 ·
     폴더 `E8B7` · 점 `E712`)과도 구분된다
  5. 다크·라이트 양쪽에서 두 아이콘 대비와 비활성 회색을 확인했다
     (**`settings.json` 의 `theme` 을 잠시 바꿔 보고 반드시 `Dark` 로 되돌린다**)
  6. 창 900 언저리 4분할에서 외부 도구가 **가장 먼저** 접히고, 이동·새로고침·알려진
     폴더는 남는다
  7. 서명된 설치본이 실제로 뜨고 페인 우클릭에서 크래시하지 않는다
- **§다음 작업 0-0** (1구간) — 닫힌 구간이므로 `HISTORY.md` 로 접거나 한 줄로 줄인다.
  **지우지는 마라** — 이 파일은 "살아 있는 것만 둔다" 가 규칙이지만 옮긴 자리를 §옮겨 간 절
  표에 남긴다
- **§반드시 알아야 하는 규칙** — 이번 구간이 새 규칙을 낳았으면 **번호를 이어서** 붙인다.
  ⚠ **중간에서 하나를 지우면 그 뒤가 전부 밀리고 컴파일러는 못 잡는다** (소스 주석이
  `§규칙 4`·`§규칙 5` 를 번호로 건다). **끝에만 붙여라**

### 6. `Directory.Build.props` 를 `0.9.0` 으로

`0.8.4 → 0.9.0`. **③을 빼먹으면 아무도 갱신되지 않는다** — 자동 업데이트는
*"설치된 버전 < 피드의 최신"* 하나로 돈다 (`scripts/pack.ps1` 머리 주석).

### 7. `.harness/HISTORY.md` §배포 기록에 `v0.9.0` 한 줄

**패키지는 이 step 에서 굽지 않는다.** *"구웠다"* 라고 적지 마라 — 실제로 굽는 것은
사용자다. 적을 것은 **버전을 올렸고 무엇이 들어갔는가**다. 배포 결과는 사용자가
`pack.ps1` 을 돌린 뒤 채운다.

### 8. `README.md` 를 볼 것

기능 목록이 있으면 외부 도구 두 줄을 늘린다. **없으면 건드리지 마라** —
있는지부터 읽어라.

## Acceptance Criteria

```bash
dotnet build --nologo -warnaserror
dotnet test --nologo --blame-hang --blame-hang-timeout 120s
pwsh -File scripts/check-structure.ps1
dotnet build -c Release --nologo -warnaserror
```

**넷 다 exit 0**, 두 `dotnet build` 는 **경고 0**. 테스트 총계가 **2093 보다 커야** 한다.

⚠ 게이트를 돌리기 전에 **`Stop-Process -Name FlexDir.Host -Force -ErrorAction
SilentlyContinue`** 를 먼저 한다. step 7·8 이 띄운 프로세스가 남아 있으면 산출물이
잠겨 빌드가 오류 수십 개를 낸다 (`.harness/HANDOFF.md` §배포 절차 ①).

2. 체크리스트:
   - `Directory.Build.props` 가 `0.9.0` 인가?
   - `ARCHITECTURE.md` 포트 표에 두 줄이 늘었는가? `HANDOFF.md` 가 **19/19** 인가?
   - `PRD-v2.md` §20 의 `FoldOrder 1` 행이 "비어 있다" 에서 바뀌었는가?
   - **문서에 적은 수치가 step 0~8 의 `summary` 에서 온 것인가?** (지어낸 값이 없는가)
   - `HANDOFF.md` §규칙 번호를 **중간에서 건드리지 않았는가?**
   - 사람 확인 일곱 항목이 `HANDOFF.md` 에 있는가?
   - `HISTORY.md` 가 굽지 않은 것을 구웠다고 적지 않았는가?
3. `phases/5-external-tools/index.json` 의 step 9 를 갱신한다:
   - 성공 → `"status": "completed"`, `"summary": "산출물 한 줄 요약"`
   - 3회 시도 후에도 실패 → `"status": "error"`, `"error_message": "구체적 원인"`

ADR 을 썼는지 여부와 그 이유를 적어라.

## 금지사항

- **`pack.ps1` 을 돌리지 마라.** 이유: 배포는 사용자가 사람 확인과 함께 한다.
- **`git push` 하지 마라.** 이유: 푸시는 사용자 지시가 있을 때만이다 (CLAUDE.md §7).
- **커밋 메시지에 AI·에이전트·생성 도구 이름을 넣지 마라.** `Co-Authored-By` 도
  `Claude-Session:` 도 넣지 마라. 이유: CLAUDE.md §7.
- **수치를 추정해서 적지 마라.** 이유: 이 저장소의 문서는 실측값으로 신뢰를 산다.
  모르면 게이트를 돌려 읽고, 못 읽으면 *"실측 전"* 이라고 적어라.
- **`HANDOFF.md` 의 §규칙 번호를 중간에서 지우거나 끼우지 마라.** 이유: 소스 주석이
  번호로 걸고 있고 컴파일러는 못 잡는다.
- **`docs/` 아래에 인수인계·메타 지시를 쓰지 마라.** 이유: `docs/*.md` 셋은 harness
  guardrails 로 매 step 프롬프트에 주입되어 모든 구현 세션을 오염시킨다
  (`.harness/HANDOFF.md` 머리 주석).
- **코드를 고치지 마라.** 이유: 이 step 은 문서와 버전이다. 코드 결함을 발견하면
  고치지 말고 `summary` 에 적고 `"status": "blocked"` 로 세워라.
- 기존 테스트를 깨뜨리지 마라.
- AC 를 통과시키려고 테스트를 삭제·스킵·약화시키지 마라.
- 이 step 에 명시되지 않은 기능이나 파일을 추가하지 마라.
