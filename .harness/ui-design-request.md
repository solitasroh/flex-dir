# flex-dir UI 시안 요청

Windows 데스크톱 파일 탐색기 앱의 UI 시안을 만들어 주세요. 결과물은 **WPF(.NET 9)로
구현**됩니다. 웹 앱이 아니라 **네이티브 Windows 앱의 목업**입니다.

## 산출물

**단일 HTML 파일 하나** + **수치 표**. 두 가지 모두 필요합니다.

1. **HTML 목업** — 외부 리소스 없이 자기완결(인라인 CSS/JS, 웹폰트 금지).
   화면 상단에 전환 컨트롤을 두어 아래 "담아야 할 화면"을 모두 볼 수 있게 해주세요.
2. **수치 표** — 마크다운 표. 목업에서 쓴 **실제 픽셀 값**을 정리합니다.
   이 표가 그대로 구현 스펙이 되므로 "적당히"가 없어야 합니다. 형식은 맨 아래 참조.

## 제품 맥락

Windows 기본 탐색기를 대체하는 앱입니다. **존재 이유는 하나** — 여러 폴더를 동시에
다루는 것. 폴더 A와 B를 나란히 놓고 파일을 옮기고 비교합니다. Q-Dir 을 쓰던 사람이
대상 사용자입니다.

**v1 범위는 의도적으로 좁습니다.** 탭·4분할·네비게이션 트리·필터·검색·그룹핑·
다크모드는 전부 제외입니다. 넣지 마세요. 대신 들어가는 것은 구멍 없이 완성돼야 합니다.

판정 기준: **하루 종일 이 앱만 쓰고 기본 탐색기를 한 번도 열지 않을 수 있는가.**

## 화면 구조

```
┌─────────────────────────────────────────────────────────┐
│ 타이틀바                                        ─ □ ✕   │
├────────────────────────────┬────────────────────────────┤
│ 툴바 (뒤로·앞으로·상위·뷰) │ 툴바                       │
│ 주소줄                     │ 주소줄                     │
├────────────────────────────┤├───────────────────────────┤
│                            ││                           │
│  파일 목록 (좌 페인)       ││  파일 목록 (우 페인)      │
│                            ││                           │
│                            ││                           │
├────────────────────────────┴┴───────────────────────────┤
│ 상태표시줄 (항목 수 · 선택 · 용량 · 오류)               │
└─────────────────────────────────────────────────────────┘
                              ↑ 드래그 가능한 스플리터
```

- 좌/우 **2분할**. 스플리터로 비율 조정. 각 페인은 **독립적인** 경로·히스토리·
  뷰 모드·정렬·선택을 가집니다.
- **툴바와 주소줄은 페인마다** 하나씩. 창 전체에 하나가 아닙니다.
- 상태표시줄은 창 전체에 하나.
- **활성 페인이 어느 쪽인지 항상 눈에 보여야 합니다.** 키보드 조작 대상이 어디인지
  모르면 2분할은 쓸 수 없습니다. 이 표현 방식을 명확히 제안해 주세요
  (테두리 / 주소줄 강조 / 헤더 색 등 — 근거와 함께).

## 담아야 할 화면

### A. 뷰 모드 4종 (필수)

같은 폴더를 네 가지 뷰로 보여주세요. **각각의 행 높이·아이콘 크기·간격이
이 시안의 핵심 산출물**입니다.

| 뷰 | 내용 |
|---|---|
| **Details** | 컬럼: 이름 · 크기 · 유형 · 수정한 날짜. 정렬 방향 표시자 포함 |
| **목록** | 이름 + 작은 아이콘. 다단(column-flow) 배치 |
| **타일** | 중간 아이콘 + 이름 + 보조정보 2줄 |
| **큰 아이콘** | 큰 썸네일 격자 + 이름 |

샘플 데이터에는 폴더, 일반 파일, 이미지 파일(썸네일 대상), 긴 이름 파일,
확장자 없는 파일을 섞어 주세요. **폴더가 파일보다 먼저** 정렬됩니다.

### B. 상태 4종 (필수)

| 상태 | 요구 |
|---|---|
| **빈 폴더** | 목록 영역과 컬럼 헤더는 유지한 채 빈 상태 메시지 |
| **권한 없음** | 상태표시줄에 사유 노출. 경로는 그대로 유지(되돌아가지 않음) |
| **열거 중** | 목록을 비우지 않고 **점진적으로 채움**. 진행 표시는 상태표시줄에 |
| **썸네일 로딩 중** | 형식 아이콘을 먼저 보이고 나중에 교체. **자리를 비워두지 않음** |

이 네 상태를 실제로 전환해 볼 수 있게 목업에 토글을 넣어 주세요.

## 비주얼 방향

**Windows 11 탐색기를 기준으로 삼되, 정보 밀도를 높입니다.**

- 시각 언어(폰트·색·아이콘 스타일·모서리)는 Windows 11 네이티브를 따릅니다.
  새 디자인 언어를 발명하지 마세요. 목표는 "이 앱이 Windows 앱처럼 느껴지는 것"입니다.
- 다만 **행 간격과 여백은 탐색기보다 조입니다.** 한 화면에 더 많은 파일이 보여야
  합니다. Q-Dir 사용자는 밀도를 원해서 옵니다.
- 폰트는 **시스템 폰트만** (Segoe UI Variable / Segoe UI). 웹폰트 금지.
- 툴바 아이콘은 **Segoe Fluent Icons** 글리프를 전제로 해도 됩니다.
- 색은 **CSS 변수로 토큰화**해 주세요. v1은 라이트만 만들지만 나중에 다크로
  갈아끼울 수 있어야 합니다. 다크 팔레트를 별도로 디자인할 필요는 없고,
  **토큰 구조만** 갖추면 됩니다.
- 시스템 강조색(accent)에 해당하는 토큰을 분리해 주세요.

### 밀도를 어디까지 조일지 — Linear 을 참고하되 스킨은 가져오지 마세요

"탐색기보다 조인다"의 기준이 필요합니다. **Linear** 의 밀도 규율을 참고하세요 —
조밀한 행 높이, 절제된 타입 스케일, 낭비 없는 크롬, 키보드 우선. 그 **규율만**
가져옵니다.

**Linear 에서 가져오지 않는 것**: 색 팔레트 · 모서리 반경 · 그림자 · 폰트 ·
그라디언트 · 아이콘 스타일. 이것들은 전부 Windows 11 에서 옵니다.

이 앱은 웹앱처럼 보이면 실패입니다. Linear 처럼 **조밀하되**, Windows 앱처럼
**생겨야** 합니다. 둘이 충돌하면 Windows 쪽이 이깁니다.

## 제약 — WPF 로 구현 가능해야 합니다

HTML 에서는 쉽지만 WPF 에서 비싸거나 불가능한 것들이 있습니다. 아래를 지켜주세요.

| 금지 | 이유 |
|---|---|
| **가변 행 높이** | 데이터 가상화(`VirtualizationMode=Recycling`)가 깨집니다. 한 뷰 안에서 모든 행은 **같은 높이**여야 합니다 |
| 목록을 감싸는 추가 스크롤 컨테이너 | WPF 에서 가상화가 완전히 해제됩니다. 스크롤은 목록 자체가 가집니다 |
| `backdrop-filter` · blur · Mica 효과 | 구현 비용이 큽니다. 불투명 배경으로 |
| 웹폰트 · 외부 아이콘 라이브러리 | 시스템 폰트와 Segoe Fluent Icons 만 |
| 파일 형식 아이콘 직접 디자인 | 아이콘은 Windows Shell 에서 옵니다. 목업에서는 **회색 자리표시자 사각형**으로 두세요 |
| 응답 지연을 가리는 애니메이션 | 느린 것을 느리지 않아 보이게 하지 않습니다 |
| 모달 대화상자로 진행 상황 표시 | 작업 중에도 반대편 페인을 쓸 수 있어야 합니다 |

또한 **우클릭 컨텍스트 메뉴는 디자인하지 마세요.** Windows Shell 이 그리는 네이티브
메뉴를 그대로 씁니다(설치된 확장을 잃지 않기 위해).

## 마지막으로

시안을 내기 전에 스스로 확인해 주세요.

- [ ] 네 가지 뷰 모두 **행 높이가 뷰 안에서 일정한가**
- [ ] 활성 페인이 한눈에 구분되는가
- [ ] 빈/오류/열거중/썸네일로딩 네 상태를 실제로 전환해 볼 수 있는가
- [ ] 탐색기보다 정보 밀도가 실제로 높은가 (같은 높이에 몇 행이 더 들어가는지 세어볼 것)
- [ ] 수치 표에 빈칸이 없는가
- [ ] 외부 리소스 참조가 없는가 (파일 하나만으로 열리는가)

판단이 갈리는 지점이 있으면 **임의로 정하지 말고 선택지와 근거를 함께 제시**해 주세요.
