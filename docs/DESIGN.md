## 1-1. 탭 줄 (2026-08-11 · 정본은 docs/PRD-v2.md §17)

**페인마다 하나**이고 페인 안 맨 위다 — 탭 줄 → 툴바 → 주소줄 → 목록 순. 창 전체에 하나가
아니라 **좌·우가 각자 갖는다**: 탭 전환에 반대편이 함께 바뀌면 페인 간 복사의 대상이
사라진다.

| 항목 | 값 |
|---|---|
| 줄 높이 | 28 (탭 24 + 위 여백 4) |
| 탭 높이 | 24 · 모서리 `4,4,0,0` — 아래로 툴바에 붙는다 |
| 탭 폭 | **최대 180 · 최소 90** 사이에서 균등 분배. 고정 탭은 **28 고정** |
| 탭 간 간격 | 2 |
| 탭 안쪽 (좌→우) | 패딩 8 · 아이콘 16 · 간격 6 · 제목 · 간격 4 · 닫기 16×16 · 패딩 4 |
| 제목 | 12 / 400 · 한 줄 말줄임. 최소 폭 90 에서 제목에 남는 자리가 **36** 이다 |
| 새 탭 `+` | 24×24 · 글리프 `E710` · **탭 줄 오른쪽 끝 고정** (스크롤 영역 밖) |
| 닫기 `×` | 16×16 버튼 · 글리프 `E8BB` 8px · 호버 `--hover` |

**넘치면 가로 스크롤이다.** 탭을 최소 90 까지 줄이고도 넘치면 탭 영역이 가로로 스크롤되고,
**활성 탭은 항상 보이는 자리로 끌려온다.** 스크롤 버튼(`‹ ›`)은 두지 않는다 — 24×2 를 더
먹는데 페인 최소 너비가 320 이다. 휠이 탭 줄 위에서 가로 스크롤이고, 그것이 탐색기와 같다.

**닫기 버튼은 항상 자리를 차지한다.** 호버할 때만 나타나게 하면 제목 폭이 그때마다 흔들린다
— 최소 폭 90 은 닫기 16 을 이미 포함한 값이다. **고정 탭에는 닫기가 없다** (먼저 고정을
풀어야 닫힌다).

| 상태 | 표현 |
|---|---|
| 활성 탭 | **위쪽 2px `--accent` 라인** · 배경 `--pane-bg` · 텍스트 `--text` |
| 비활성 탭 | 배경 투명 · 텍스트 `--text-2` · 호버 `--hover`. **라인 자리는 그대로 두고 색만 투명이다** — 전환할 때 글자가 2px 튀지 않는다 |
| 고정 탭 | 폭 28 · 아이콘만 중앙 · 제목과 닫기 없음 · 줄 맨 왼쪽에 모인다 |
| **비활성 페인의 탭 줄** | 크롬 배경 강등 규칙을 그대로 따른다 (§6) — 줄 배경이 `--win-bg` 로 내려간다 |

> **라인이 붙은 것은 실물이 그것을 요구했기 때문이다** (2026-08-11 · 사용자 결정).
> 처음에는 배경색만으로 갈랐고 근거를 *"목록과 같은 색이라 아래로 이어져 보인다"* 로 적었는데,
> **페인 안 순서가 탭 줄 → 툴바 → 주소줄 → 목록이라 탭 아래에 오는 것은 목록이 아니다.**
> 이어붙일 대상이 없으니 그 색을 쓸 이유도 함께 사라졌는데 색만 남았고, 남은 대비는
> `--pane-bg`(`#FFFFFF`)와 활성 페인 줄 배경 `--chrome-bg`(`#F9F9F9`)의 **6/255** 뿐이었다 —
> 사용자가 실물에서 *"활성 탭이 구분되지 않는다"* 고 했다.
> 라인은 §6 이 활성 페인에 쓰는 관용구(`하단 2px accent`)와 같은 것이고, 색 대비에 기대지
> 않아 다크 전환에도 살아남는다. **배경 `--pane-bg` 는 그대로 둔다** — 근거는 잃었지만 활성
> 탭이 밝은 쪽이라는 방향은 맞다.

**툴팁은 전체 경로다.** 제목이 말줄임되거나 사용자가 제목을 바꿔 놓았을 때 어디인지 아는
길이 그것뿐이다.

### 탭 드래그 중

| 상태 | 표현 |
|---|---|
| 끌리는 탭 | 원래 자리에 반투명(40%)으로 남는다 — 놓으면 어디로 가는지와 어디서 왔는지가 함께 보인다 |
| 삽입 위치 | 탭 사이에 **2px `--accent` 세로선** (높이 24). 탭이 실시간으로 밀리지 않는다 — 밀면 좁은 페인에서 목표가 계속 움직인다 |
| 다른 페인의 탭 줄 위 | 그 줄 전체에 `--sel` 배경. **페인을 건너간다는 것이 줄 단위로 보여야 한다** |
| 드롭 불가 자리 | 표시를 그리지 않는다. 놓으면 제자리로 돌아간다 |

**새 탭은 활성 탭 바로 오른쪽에 서고 즉시 활성이 된다** (docs/PRD-v2.md §17). `Ctrl+T` 가
지금 폴더를 **복제**하므로 같은 제목 둘이 나란히 서는데, 새것이 오른쪽이라는 규칙이
그것을 가른다.

**탭을 전환하면 키보드 포커스가 그 탭의 목록으로 간다.** 탭에 포커스가 남으면 방향키가
목록을 움직이지 않아 고장으로 보인다. 활성 페인 표시(§6)도 그 페인으로 옮겨간다 —
탭 클릭은 항목 클릭과 같은 규칙이다 (docs/PRD-v2.md §15).

## 2. 뷰 모드별

| 뷰 | 행 높이 | 아이콘 크기 | 항목 간 가로 간격 | 항목 간 세로 간격 |
|---|---|---|---|---|
| Details | 24 | 16 | — (컬럼 패딩 좌우 8) | 0 |
| 목록 | 22 | 16 | 12 (항목 폭 200 고정) | 0 |
| 타일 | 56 | 32 | 8 (최소 폭 220, 가변) | 4 |
| 큰 아이콘 | 140 (항목 116×140) | 96 (썸네일 96×96) | 8 | 8 |

- Details 컬럼 헤더 높이 **24**.
- Details **그룹 헤더 높이 28** (ADR-017). 좌우 패딩 8 · 글리프(8px) + 라벨(12 semibold) +
  개수(11, `Text2`). 행 높이 24 보다 높은 것은 의도다 — 같으면 항목과 구분되지 않는다.
- 큰 아이콘 이름은 **2줄 말줄임** (줄 높이 14, 최대 28).

> **행 높이는 뷰 안에서 고정이다.** 가변으로 바꾸면
> `VirtualizationMode=Recycling` 이 깨진다 (ARCHITECTURE §5).

## 3. Details 컬럼

| 컬럼 | 기본 너비 | 정렬 |
|---|---|---|
| 이름 | 320 | 왼쪽 |
| 크기 | 90 | 오른쪽 |
| 유형 | 120 | 왼쪽 |
| 수정한 날짜 | 140 | 왼쪽 |

**넷 다 픽셀이고 사용자가 끈다** (2026-08-10 · 정본은 docs/PRD-v2.md §11). 헤더 경계를
끌면 **그 컬럼만** 변하고 오른쪽은 폭을 지킨 채 밀린다 — 탐색기와 같다. 남는 자리는 맨 뒤의
빈 열이 먹는다.

- 이름이 `*`(나머지 전체)이던 것은 **끌 수 있게 되면서 폐기됐다.** 한 열을 늘리면 다른 열이
  줄어드는 시소가 되기 때문이다.
- 컬럼별 최소 너비도 폐기됐다. 하한은 `PaneViewModel` 이 **넷에 같은 값**(48)으로 자르고,
  상한은 800 이다. 컬럼마다 다른 하한을 두면 `ColumnSync` 가 편 폭과 다투게 된다.
- **폭은 페인마다 따로 기억한다.** 폴더가 바뀌어도 유지되고 창을 닫을 때 저장된다.

## 7. 아이콘 (Segoe Fluent Icons)

| 버튼 | 글리프 |
|---|---|
| 뒤로 | `E72B` |
| 앞으로 | `E72A` |
| 상위 폴더 | `E74A` |
| 새로 고침 | `E72C` |
| 뷰 — 자세히 / 목록 / 타일 / 큰 아이콘 | `E8A4` / `E8FD` / `E8A9` / `E15B` |
| 분류 방법 (드롭다운) | `E8EC` |
| 캡션 — 최소화 / 최대화 / 복원 / 닫기 | `E921` / `E922` / `E923` / `E8BB` |
| 탭 — 새 탭 / 탭 닫기 | `E710` / `E8BB` (§1-1) |
| 탭 아이콘 (탭 왼쪽) | `E8B7` (폴더) — **아래 예외 참조** |

목업에서는 뷰 아이콘을 인라인 도형으로 대체했다. 구현에서는 위 글리프를 쓴다.

> 큰 아이콘은 원래 `E8A6` 이었다. **실물에서 잠긴 문서(ProtectedDocument)로 그려져** 큰
> 사각 하나(`E15B`)로 바꿨다 — 타일의 작은 사각 넷(`E8A9`)과 한눈에 갈린다.
> 글리프는 이름이 아니라 코드포인트로 가므로 표를 실물로 한 번은 봐야 한다.
>
> 분류도 같은 자리를 두 번 밟았다. 처음에 `E8FD` 를 썼는데 **그것이 목록 뷰 버튼과 같은
> 글리프라** 툴바에 같은 아이콘이 둘 생겼다. 후보를 GDI+ 로 그려 `F168`(묶인 목록)로
> 바꿨지만 **30px 로 그려 놓고 골라서** 또 틀렸다 — 실제 크기 16px 에서는 선 텍스처가
> `E8A4`·`E8FD` 와 같은 계열로 보여 눈에 걸리지 않는다.
>
> **툴바 아이콘은 툴바 맥락에서, 실제 크기로 고른다.** 이 툴바에는 계열이 둘 있다 —
> 선(`E8A4`·`E8FD`)과 사각(`E8A9`·`E15B`). 새 아이콘은 **둘 중 어느 쪽도 아닌 실루엣**
> 이어야 눈이 멈춘다. 그래서 `E8EC`(태그)다.

파일·폴더 아이콘은 **디자인 대상이 아니다.** Windows Shell 에서 온다 (SHELL_NOTES §아이콘).

> **탭 아이콘만 예외다 — 글리프 `E8B7` 을 쓴다** (사용자 결정 2026-08-12).
> 규칙대로 shell 아이콘을 쓰려면 `PaneViewModel` 이 자기 폴더의 아이콘을 내야 하는데
> **그것이 저장소 호출이다** (`CLAUDE.md` §3) — 그리고 탭은 8개까지 열리므로 그 비용이
> 탭 수만큼 곱해지고, **배경 탭에서도 나간다.** v1 이 유일하게 성공한 축이 성능이라
> (`docs/PRD-v2.md` §3 의 3번) 여기서 값을 치를 자리가 아니다.
>
> 대가는 명시한다: **드라이브 루트와 네트워크 공유도 폴더 아이콘으로 그려진다.** 목록과
> 트리에서는 그 셋이 갈리는데 탭에서만 같아 보인다 — 탭 제목이 `C:\` 와 공유 이름으로
> 이미 갈리므로 감수한다. 이 값은 **고른 것이지 관측된 것이 아니다** (§17).

## 9. 키보드 맵

**충돌하면 탐색기가 이긴다** (`UI_GUIDE.md` 원칙 1). v1 의 판정 기준이 "기본 탐색기를 열
이유가 0" 이므로(`PRD.md` §1) 근육 기억을 그대로 가져오는 것이 기능 하나보다 중요하다.

### 탐색기와 같은 것

| 키 | 동작 | 대상 |
|---|---|---|
| `Alt+←` / `Alt+→` | 뒤로 / 앞으로 | 활성 페인 |
| `Alt+↑` | 상위 폴더 | 활성 페인 |
| `F5` | 새로 고침 | 활성 페인 |
| `Ctrl+L` · `Alt+D` | 주소줄 편집 시작 (breadcrumb → 입력 상자, §9-1) | 활성 페인 |
| `Enter` | 열기 (폴더 진입 / 연결 프로그램) | 포커스 항목 |
| `Ctrl+C` / `Ctrl+X` / `Ctrl+V` | 복사 / 잘라내기 / 붙여넣기 | 선택 |
| `Delete` | 휴지통 | 선택 |
| `F2` | 이름 변경 | 선택 1개일 때만 |
| `Ctrl+Shift+N` | 새 폴더 | 활성 페인의 현재 폴더 |
| `Ctrl+A` | 전체 선택 | 활성 페인 |
| 문자 키 | type-ahead — 그 이름으로 점프 | 활성 페인 |

### 마우스 보조 버튼 (2026-08-11 · 사용자 요청)

| 버튼 | 동작 | 대상 |
|---|---|---|
| 4번 (`XButton1`) | 뒤로 | **커서 아래 페인** — 그 페인이 활성이 된다 |
| 5번 (`XButton2`) | 앞으로 | 〃 |

**대상 규칙이 키보드와 다르다.** `Alt+←` 는 활성 페인 하나로 가는데 마우스에는 **자리가
있다** — 오른쪽 페인 위에서 4번을 누르면 왼쪽이 활성이어도 오른쪽이 움직인다. 항목 클릭이
그 페인을 활성으로 만드는 것과 같은 규칙이다. 페인 밖(트리·툴바·상태표시줄)에서 누른 것은
활성 페인으로 간다 — 창 안에서 누른 버튼이 아무 일도 하지 않으면 고장으로 보인다.

**가운데 버튼을 뒤로/앞으로에 쓰지 않는다** (사용자 결정) — 탐색기에 없는 매핑이라 근육
기억에 없다. 상위 폴더는 `Alt+↑` 와 툴바 버튼에 있다.

> **그 결정은 뒤로/앞으로에 한한 것이었다.** 2026-08-11 에 가운데 버튼이 **새 탭 열기**로
> 들어왔다 (docs/PRD-v2.md §17) — 그쪽은 브라우저·탐색기와 같은 자리라 근육 기억에 이미
> 있다. 목록의 폴더 위에서는 **그 폴더를 새 탭으로**, 탭 위에서는 **그 탭 닫기**, 트리
> 항목 위에서는 **활성 페인에 새 탭**이다.

### 탭 (2026-08-11 · 정본은 docs/PRD-v2.md §17)

**바꾸는 키가 없다.** 아래 일곱 조합이 전부 비어 있음을 `MainWindow.xaml` 의 `KeyBinding`
전수로 확인했다.

| 키 | 동작 |
|---|---|
| `Ctrl+T` | 새 탭 — **활성 페인**에, **지금 폴더를 복제**해서 |
| `Ctrl+W` | 활성 탭 닫기. **탭이 1개거나 고정 탭이면 무시된다** |
| `Ctrl+Tab` / `Ctrl+Shift+Tab` | 다음 / 이전 탭 (활성 페인 안에서 순환) |
| `Ctrl+PageDown` / `Ctrl+PageUp` | 〃 — 같은 동작의 두 번째 자리 |
| `Ctrl+Shift+T` | 닫은 탭 되살리기. **창 전체에 스택 하나** · 깊이 10 · 원래 페인의 원래 자리로 |

**`Ctrl+숫자`를 탭 번호에 주지 않는다.** 브라우저·탐색기가 그 자리를 탭에 쓰지만 이 앱에서는
이미 **정렬**이고(위 §뷰와 정렬) 매일 눌리는 키다. 탭이 2~4개인 화면에서는 `Ctrl+Tab`
순환으로 닿는다. `Alt+숫자`도 비워 둔다 — 관습에 없는 자리에 번호를 만들면 아무도 찾지
않는다.

**`Tab`·`F6` 은 페인 전환 그대로다.** 탭 전환에 주지 않는다 — 페인 전환은 분할의 근간이고
이 앱에서 가장 자주 눌린다. **화면 순서로 순환한다** (docs/PRD-v2.md §18) — 같은 키를 분할
수만큼 누르면 제자리로 와야 4분할에서 길을 잃지 않는다. 1분할이면 아무 일도 하지 않는다.

### 탐색기에 없는 것 (빈 조합을 쓴다)

| 키 | 동작 |
|---|---|
| `Tab` · `F6` | 페인 전환 (탭 전환이 아니다 — 위 §탭) |
| `Ctrl+Alt+C` | 선택을 **다른 페인** 폴더로 **복사** |
| `Ctrl+Alt+M` | 선택을 **다른 페인** 폴더로 **이동** |
| `Ctrl+Alt+O` | **다른 페인**의 폴더를 이쪽 페인에서 연다 |

**'다른 페인' 은 직전에 활성이던 페인이다** (docs/PRD-v2.md §18 · 사용자 결정 2026-08-12).
2분할에서는 그것이 곧 반대편이라 예전 동작과 한 글자도 다르지 않다. **1분할에서는 셋 다
아무 일도 하지 않는다** — 갈 곳이 없다.

`Tab` 이 페인 전환이므로 툴바·주소줄로의 포커스 순환은 없다. 구멍은 없다 — 툴바 동작은
전부 위 표에 있고 주소줄은 `Ctrl+L`·`Alt+D` 로 직접 간다.

### 뷰와 정렬

화면의 순서(툴바 버튼 · Details 컬럼)와 숫자를 일치시킨다.

| 키 | 동작 | | 키 | 동작 |
|---|---|---|---|---|
| `Ctrl+Shift+1` | 자세히 | | `Ctrl+1` | 이름순 |
| `Ctrl+Shift+2` | 목록 | | `Ctrl+2` | 크기순 |
| `Ctrl+Shift+3` | 타일 | | `Ctrl+3` | 유형순 |
| `Ctrl+Shift+4` | 큰 아이콘 | | `Ctrl+4` | 수정한 날짜순 |

정렬은 **같은 키를 다시 누르면 방향만 반전**한다 (`PaneViewModel.ChangeSortAsync` 가 이미
그렇게 동작한다). 탐색기의 뷰 단축키는 `Ctrl+Shift+1~8` 이지만 우리 뷰는 4종이므로 번호를
1~4 로 다시 매긴다 — 탐색기 번호를 그대로 쓰면 툴바 버튼 4개와 번호가 어긋난다.
`Ctrl+숫자`는 탐색기에서 비어 있으므로 빼앗는 것이 없다.

**분류(그룹화)에는 단축키를 두지 않는다** (ADR-017). 조작은 둘이다 — **툴바의 분류
드롭다운**(`F168`, §7)과 **Details 컬럼 헤더 우클릭**. 기준은 정렬과 같은 넷(이름·크기·
유형·수정한 날짜)에 "없음" 을 더한 다섯이고, 그룹 헤더를 **클릭하면 접힌다.** 접힌 그룹은
폴더별로 기억한다.

> **처음에는 헤더 우클릭 하나만 두었고 그것이 틀렸다.** 탐색기와 같은 자리라는 이유였는데,
> 탐색기는 리본에도 같은 항목을 둔다. 만든 사람이 설명해야 찾을 수 있으면 잘못 고른
> 자리다 — 사용자가 실물에서 못 찾았다 (2026-08-07). 툴바 드롭다운이 주 진입점이고
> 헤더 우클릭은 아는 사람을 위한 지름길로 남긴다.
>
> **항목 다섯은 `PaneViewModel.GroupOptions` 가 소유한다.** 두 진입점이 같은 목록을 쓰므로
> XAML 두 곳에 두 벌 쓰지 않고, 어느 것이 켜져 있는지가 ViewModel 테스트로 채점된다.
> 툴바 드롭다운은 Details 가 아니면 비활성이다.

**접힌 그룹의 항목은 키보드가 건너뛴다.** 화면에 없는 줄에 포커스가 앉으면 스크롤이 엉뚱한
자리로 간다 — `Home`·`End`·`PageUp/Down` 도 밟을 수 있는 항목 위에서만 움직인다.

### 이동과 선택은 ViewModel 이 처리한다

`ListView` 의 내장 키보드 처리를 쓰지 않는다. 뷰 3종이 합성 행 위에 서므로
(`ARCHITECTURE.md` §5) 내장 이동은 **행 단위**로 움직여 칸 단위 이동이 되지 않는다.

| 키 | 동작 |
|---|---|
| `↑` `↓` `←` `→` | 포커스 이동. 합성 행 위에서는 2D — `↓` 는 한 열 수만큼 뒤 |
| `Shift+방향` | 앵커부터 범위 선택 (`PaneSelection.SelectRange`) |
| `Ctrl+방향` | 선택을 바꾸지 않고 포커스만 이동 |
| `Ctrl+Space` | 포커스 항목 선택 토글 (`PaneSelection.Toggle`) |
| `Home` / `End` | 처음 / 마지막 |
| `PageUp` / `PageDown` | 뷰포트 한 화면 |

**목록 뷰에서는 방향이 뒤집힌다** — 세로로 채우고 다음 열로 넘어가므로 `↓` 가 같은 열
아래, `→` 가 다음 열이다.

## 9-1. 상호작용 상태

### 이름변경 인라인 편집

| 제스처 | 결과 |
|---|---|
| `F2` · 선택 항목 재클릭 | 편집 시작 (선택이 정확히 1개일 때만) |
| `Enter` | 확정 |
| `Esc` | 취소 |
| **포커스 상실** | **취소** |

**포커스 상실이 취소인 것은 탐색기와 다른 유일한 지점이다.** 분할이라 다른 페인 클릭이
일상 동작이어서 탐색기에 없는 포커스 상실 경로가 하나 더 있고, 이름변경은 휴지통이 없는
유일한 조작이다 — 잘못 확정되면 되돌릴 방법이 없다.

- 편집기의 초기 선택 범위는 **파일은 확장자 제외, 폴더는 전체** (탐색기와 같다).
- 편집 중에는 방향키·단축키가 목록으로 새지 않는다.
- **편집할 행이 아직 없을 수 있다.** `새 폴더`(`Ctrl+Shift+N`)는 폴더를 만든 뒤
  `RenamingName` 을 세우지만 그 폴더가 목록에 들어오는 것은 감시 갱신이다. View 는
  `RenamingName` 과 목록을 함께 보고 **그 이름이 나타나는 순간** 편집기를 연다.
- 이름이 비었거나 그대로면 조작 없이 편집만 닫힌다 (`CommitRenameAsync` 가 이미 그렇다).

### 주소줄 — breadcrumb 과 입력 상자

평소에 보이는 것은 **경로 칸(breadcrumb)** 이고, 입력 상자는 편집할 때만 나온다.
같은 자리에서 갈리므로 둘이 동시에 보이는 순간은 없다.

| 제스처 | 결과 |
|---|---|
| 칸 클릭 | 그 칸까지의 경로로 이동 |
| 칸 오른쪽 빈 자리 클릭 | 편집 시작 |
| `Ctrl+L` · `Alt+D` | 편집 시작 + 전체 선택 |
| `Enter` | 입력한 경로로 이동 |
| `Esc` | 되돌리고 breadcrumb 으로 |
| **포커스 상실** | breadcrumb 으로 (입력은 버린다) |

- 구분자(`›`)는 **칸 사이에만** 들어간다. 마지막 칸 뒤에는 없다.
- 드라이브 루트는 보일 때 `C:`, 갈 때 `C:\` 다 — `C:` 는 드라이브 상대 경로라 거부된다.
- **이동이 끝나면 항상 breadcrumb 으로 돌아온다.** 그러지 않으면 한 번 편집한 페인이
  영영 칸을 보여주지 않는다.

### 스플리터 드래그 중

- 호버·드래그 중 스플리터에 `--splitter-hover` 세로 바 (목업 그대로).
- 좌우 페인 최소 너비 320 에서 멈춘다 (§1).
- **목록은 열 수가 바뀔 때만 다시 배치한다.** 폭이 변해도 열 수가 그대로면 아무것도 하지
  않는다 (`ARCHITECTURE.md` §5). 드래그 중에도 즉시 반영한다 — 놓기 전에 결과를 봐야 한다.
- 시간 디바운스를 쓰지 않는다. 경계가 실행 속도에 따라 달라지면 원인을 찾을 수 없다.

### 페인 간 드래그앤드롭

| 수정키 | 결과 |
|---|---|
| 없음 | **복사** |
| `Shift` | 이동 |
| `Ctrl` | 복사 (명시) |
| `Alt` | 없음 — 바로가기는 v1 범위 밖 |

**기본이 복사인 것은 탐색기와 다르다.** 탐색기는 같은 볼륨이면 이동인데, 분할 화면에서는
드래그가 일상 조작이라 같은 손동작이 대상에 따라 원본을 지우기도 안 지우기도 하면 사고가
난다. 분할 파일 관리자 계보(Total Commander)의 기본도 복사다.

| 드롭 대상 | 결과 |
|---|---|
| 페인의 빈 공간 | 그 페인의 현재 폴더 |
| 폴더 항목 위 | 그 폴더 안 |
| 파일 항목 위 | 페인의 현재 폴더로 취급 |
| 같은 폴더로 이동 | 아무 일도 하지 않음 (`MoveSelectionToAsync` 가 이미 그렇다) |

**양방향이다** — 밖에서 받고 밖으로 내보낸다. `FlexDir.Shell` 을 쓰지 않는다: WPF
`System.Windows.DataObject` 가 `SetFileDropList`·`DataFormats.FileDrop`·임의 포맷
(`Preferred DropEffect`)을 모두 제공하고 CF_HDROP 마샬링을 대신한다. 포트를 늘리지 않고
`PaneViewModel` 에 `DropAsync(paths, targetFolder, isMove)` 만 는다.

드래그 시작 임계값은 `SystemParameters.MinimumHorizontalDragDistance` 를 따른다.
