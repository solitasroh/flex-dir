# UI_GUIDE — flex-dir

이 문서는 **매 step 프롬프트에 주입된다.** 짧게 유지한다.
구체 수치와 시각 스펙은 `DESIGN.md`.

## 원칙

1. **새 시각 언어를 발명하지 않는다.** Windows 11 탐색기를 기준으로 삼는다.
   목표는 "네이티브 앱처럼 손에 붙는 것" 이다. 전작은 이 지점에서 실패했다.
2. **키보드로 완주할 수 있어야 한다.** 마우스로만 되는 동작을 만들지 않는다.
3. **작업 중에 UI 가 멈추지 않는다.** 오래 걸리는 일은 취소할 수 있어야 한다.
4. **선택은 함부로 잃지 않는다.** 정렬·갱신·뷰 전환·감시 갱신 후에도 유지한다.

## 금지 목록

| 금지 | 이유 |
|---|---|
| `*.xaml.cs` 에 로직 | god object 가 자라는 자리. 전작 `main-window.cpp` 2,836줄의 재발 |
| `ItemsControl` 을 `ScrollViewer` 로 감싸기 | 데이터 가상화가 완전히 해제된다 |
| `IsVirtualizing="False"` | 위와 같음 |
| 가변 행 높이 | `VirtualizationMode=Recycling` 과 상충 — **예외 하나: 그룹 헤더 28 (항목 24)**. 아래 참조 |
| UI 스레드에서 shell·I/O 호출 | 네트워크 경로에서 초 단위로 멈춘다 |
| 모달 대화상자로 진행 상황 표시 | 작업 중 다른 페인을 못 쓰게 된다 |
| 커스텀 컨텍스트 메뉴로 shell 메뉴 대체 | 설치된 확장이 사라지면 탐색기를 열게 된다 |
| 자체 아이콘·썸네일 캐시 구축 | shell 캐시를 쓴다. 중복 캐시는 어긋난다 |
| 애니메이션으로 응답을 가리기 | 느린 것을 느리지 않아 보이게 하지 않는다 |

**가변 행 높이의 예외 — 그룹 헤더 28** (ADR-017). 금지의 이유는 "재활용되는 컨테이너가
서로 다른 높이를 오가며 스크롤이 튄다" 인데, 이 자리에서는 그 이유가 성립하지 않는다.

- **템플릿이 하나다** (`DetailsGroupedRow`). 헤더와 항목이 같은 템플릿의 트리거로 갈리므로
  컨테이너 재활용이 종류를 넘나들지 않는다. 뷰마다 다른 템플릿을 쓰는 것과 다른 상황이다.
- **`ScrollUnit="Item"` 이라 스크롤 축이 픽셀이 아니라 항목 수다.** 높이가 섞여도 스크롤
  계산이 어긋나지 않는다. 이 값이 `Pixel` 로 바뀌면 예외가 무효가 된다.
- **대가는 PageUp/Down 이 근사가 되는 것이다.** `PaneViewModel` 의 `*Pitch` 상수는 항목
  높이 24 에서 나오는데 헤더가 그보다 높다. 그룹화를 켠 화면에서 한 번에 넘어가는 양이
  화면과 정확히 같지 않다 — 헤더가 항목이 아니라는 점에서 어차피 근사다.

높이를 24 로 맞추면 위 셋이 전부 사라지지만 헤더가 항목과 구분되지 않는다.
**그래서 예외를 두되 이유가 성립하는 조건을 여기 적어 둔다.**

## 상태 표현

| 상태 | 표현 |
|---|---|
| 열거 중 | 목록을 비우지 않고 점진적으로 채운다. 진행 표시는 상태 표시줄에 |
| 빈 폴더 | 목록 영역을 유지한 채 빈 상태 메시지 |
| 권한 없음 | 상태 표시줄에 사유. 경로는 그대로 둔다 |
| 썸네일 로딩 중 | 형식 아이콘을 먼저 보이고 나중에 교체. 자리를 비워두지 않는다 |
| 형식 아이콘 도착 전 | **자리표시자를 그리지 않는다** — 빈 칸이다. 목업의 회색 사각형은 shell 아이콘의 대역이었고 실물에는 그것이 있다 (B-3). 확장자마다 한 번뿐인 조회라 이 구간은 짧다 |
| 활성 페인 | 항상 시각적으로 구분되어야 한다. 키보드 조작 대상이 어디인지 |
